# 计划 1：墨舟 BookMate — 书籍推荐 / 解析 / 伴读智能客服系统

## 目标

- 交付一个可启动的后端服务（FastAPI）与配套前端（Jinja2 + 原生 JS），实现：按性格与目标推荐书籍、书籍解析、导读计划、伴读、阅读历史记忆、多轮智能客服与四域业务接口适配。
- 代码量达到课程交付线：Python ≥ 5,000 行（预算 ~6,000 行，含测试），HTML ≥ 1,700 行（预算 ~1,900 行，不含 CSS/JS）。
- RAG 全链路（入库 → 切片 → 向量化 → 检索 → 重排 → 引用生成 → 评测调优）可实际跑通；RAGAS 指标落 CSV，并由 LLM 产出调优建议。
- 部署形态：本地 Docker 容器化先跑通（仅承载 MySQL/Redis/Qdrant/应用/队列），LLM/Embedding/Rerank 全部走在线 API，本地不加载模型；上线阶段迁移腾讯云并具备健康检查、烟雾测试与回滚路径。
- 开箱即用：首次启动自动建表、导入内置书目、自动入库语料并完成检索自检；新增语料可被自动发现并入队。

find app tests scripts -name "*.py" -print0 | xargs -0 wc -l

docker compose -f deploy/compose/docker-compose.cpu.yml up -d   # 上线阶段使用；本地用 dev.yml

## 风险点

| 风险 | 影响 | 缓解 / 回退 |
| --- | --- | --- |
| 无真实书稿/版权 | 解析与 RAG 无内容 | 先内置公版书 + 用户提供授权语料；缺失时用 3 本公版书跑通并标注 |
| LLM API 限额/不可用 | 推荐解释、解析、聊天失败 | 固定 mock LLM 用于测试；运行时降级为规则+抽取式回答；错误码明确 |
| 在线 API 限流/故障 | 推荐、解析、聊天、评测质量下降 | 重试+并发限制+缓存；重排失败按 RRF 降级；关键路径返回 `degraded`；评测缓存 judge 结果 |
| 在线 API 成本超预算 | 评测与解析费用不可控 | 单次评测限额、结果缓存、解析缓存、并发上限；月度预算告警 |
| 远程服务器权限/网络未知 | 无法部署 | 先本机 compose 验证；部署交用户执行或授权后执行；提供一键脚本 |
| Docker 守护进程未启动 | 本地无法容器验证 | 文档标注前置；用户启动 Docker Desktop 后复验 |
| 四域接口契约未知 | 工具调用不可用 | 定义适配接口 + mock；真实 URL 到达后只改配置 |
| 代码量达标压力 | 为凑行数引入低质代码 | 以模块预算表推进；用测试与真实功能自然达标，禁止空行/注释凑数 |
| 评测成本 | RAGAS 调用费用 | 黄金集 50 条、限制并发、缓存 judge 结果、单次预算上限 |

## 决策记录

| ID | 决策 | 理由 | 撤销条件 |
| --- | --- | --- | --- |
| D1 | LLM 走 OpenAI 兼容 API（默认 SiliconFlow），可切本地 | 用户已有该生态；开发期无需 GPU 跑大模型 | 明确要求全本地/离线 |
| D2 | 向量库 Qdrant | 过滤+快照+部署成熟；比 Chroma 更适合多租户过滤 | 要求单文件嵌入式 → Chroma |
| D3 | 关系库 MySQL 8 | 事务、迁移、运维成熟；与技能栈一致 | 团队强制 PostgreSQL |
| D4 | 前端 Jinja2 + 原生 JS | 无构建链、部署简单、满足 HTML 行数要求 | 要求 React/Vue SPA |
| D5 | 模型全在线：LLM/Embedding/Rerank 走 API；本地 Docker 不加载模型 | 用户明确要求；本地无需 GPU；部署简单、成本可控 | 在线成本过高或要求离线 → 自建 GPU 推理（后续项） |
| D6 | 四域接口先 mock 后真实 | 契约未提供，先保证全链路可跑 | 用户提供真实接口文档 |
| D7 | 评测用 RAGAS + LLM judge | 行业通用、指标可解释 | 评测成本过高 → 自定义轻量指标 |

## 6. 验收中发现并修复的缺陷

1. **201/202 状态码被吞**：`ok()` 显式返回 `ORJSONResponse`，覆盖了路由装饰器的
   `status_code`，OpenAPI 声明 201 实际返回 200。已让 `ok()` 显式接收状态码并修正
   13 个创建/异步接口，新增回归测试。
2. **规则计划预标最后一天完成**：LLM 降级时最后一天创建即 `done`，导致无法打卡。
   已改为全部 `pending`。
3. **规则计划漏掉最后一章**：章节分配越界后回退索引，41 章只分到 40 章。已重写
   分配上界，并补“天数多于章节”的复盘分支。
4. **打卡完成天数重复 +1**：统计已完成天数的查询已包含本次打卡，又额外 `+1`，
   首次打卡显示 2/5。已去除重复累加。
5. **导读提示词未强制覆盖全书**：模型只排到第 28/41 章，导致规则兜底。已把
   “恰好 N 天、首章/末章、连续不重叠覆盖”写成硬性要求，改后 LLM 计划
   `degraded=false`。

## 8. 已知限制与上线前待办

- **腾讯云部署未执行**：需用户提供服务器 IP、SSH 用户/密钥、域名（可选）与
  `.env` 生产值；CPU 与 GPU compose 已分离，GPU 侧默认不启动任何服务。
- **Nginx 未运行时验证**：本地无法拉取 `nginx:1.27-alpine`；配置已完成静态检查，
  首部署时需确认 SSE 关闭缓冲、`/metrics` 内网限制与限流生效。
- **HTTPS 未启用**：Nginx 中留有 443 模板，待域名与证书。
- **黄金集 19 条**（目标 50 条）：当前指标可复现，但样本量偏小。
- **单 API 实例**：当前 compose 为单副本；横向扩容前需把限流/会话状态完全外置
  （已在 Redis），并评估 Qdrant/MySQL 连接数。
- **在线模型依赖**：SiliconFlow 不可用时，问答会走抽取式兜底，计划/伴读走规则兜底；
  延迟与质量受网络影响。
- 生产部署请使用 `scripts/deploy.sh`（自动生成 `prod-<时间戳>` 标签）；
  直接执行 compose 时注意 `.env` 的 `IMAGE_TAG=dev` 只适用于本机开发。

## 9. 复现命令

```bash
# 本地开发栈
docker compose --env-file .env -f deploy/compose/docker-compose.dev.yml up -d --build

# 单元测试
docker compose --env-file .env -f deploy/compose/docker-compose.dev.yml exec -T api pytest -q

# 端到端（真实在线模型）
docker compose --env-file .env -f deploy/compose/docker-compose.dev.yml \
  exec -T api python scripts/e2e_acceptance.py --base-url http://127.0.0.1:8000

# 生产镜像本机演练（不含 Nginx）
docker compose --env-file .env -f deploy/compose/docker-compose.cpu.yml \
  up -d mysql redis qdrant init api worker
docker compose --env-file .env -f deploy/compose/docker-compose.cpu.yml \
  exec -T api python scripts/e2e_acceptance.py --base-url http://127.0.0.1:8000
```
